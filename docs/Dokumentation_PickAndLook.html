a) Spezifikation und Design

1. Ziel der Anwendung

Pick and Look ist eine webbasierte Anwendung, die Nutzern eine plattformunabhängige Anlaufstelle bietet, um schnell und gezielt passende Filme und Serien zu entdecken – unabhängig davon, auf welchem Streaming-Dienst diese verfügbar sind. Im Gegensatz zu einzelnen Streaming-Plattformen, die ausschließlich ihren eigenen Katalog empfehlen, ermöglicht Pick and Look stimmungs- und interessenbasierte Empfehlungen über verschiedene Anbieter hinweg.

4. Use Cases (angepasst an tatsächliche Implementierung)

UC1 – Registrieren / Einloggen

Akteure: Alle Benutzer

Beschreibung: Die Authentifizierung wird vollständig über den externen Dienst Auth0 abgewickelt. Benutzer können sich mit E-Mail und Passwort registrieren oder einloggen. Auth0 übernimmt die Validierung der Zugangsdaten und verwaltet die Sitzung über JWT-Tokens. Nach erfolgreichem Login werden personalisierte Funktionen (Merkliste, Profil) freigeschaltet.

Benutzer AktionErgebnis
Klick auf „Login" in der NavbarAuth0-Login-Seite öffnet sich
Eingabe von E-Mail und PasswortWeiterleitung zurück zur Anwendung, Benutzer ist eingeloggt
Klick auf „Logout"Sitzung wird beendet, Weiterleitung zur Startseite

UC2 – Inhalt anzeigen

Akteure: Alle Benutzer (kein Login erforderlich)

Beschreibung: Alle Benutzer können die vollständige Film- und Serienliste einsehen. Jeder Eintrag zeigt Titel, Typ (Film/Serie), Genre, Erscheinungsjahr und Durchschnittsbewertung. Per Klick auf einen Film öffnet sich die Detailansicht mit vollständiger Beschreibung.

Benutzer AktionErgebnis
Klick auf „Filme" in der NavbarÜbersicht aller Filme und Serien
Klick auf einen FilmDetailansicht mit Beschreibung, Genre, Bewertung

UC3 – Inhalt filtern und suchen

Akteure: Alle Benutzer

Beschreibung: Auf der Filmübersicht können Benutzer nach Titel suchen sowie nach Typ (Film/Serie), Genre, Erscheinungsjahr und Mindestbewertung filtern. Mehrere Filter können kombiniert werden. Das Backend führt die Filterung serverseitig durch.

FilterBeschreibung
TitelsucheFreitextsuche (case-insensitiv, Teilstring)
TypFilm oder Serie
GenreAuswahl aus vorhandenen Genres
ErscheinungsjahrVon-Bis-Bereich
Mindestbewertung0.0 – 10.0

UC4 – Profil verwalten

Akteure: Registrierter Benutzer

Beschreibung: Eingeloggte Benutzer können ihr Profil mit persönlichen Daten (Name, Adresse, Stadt, Telefon) befüllen und aktualisieren. Die E-Mail-Adresse wird von Auth0 übernommen und kann nicht geändert werden. Die Daten werden im Backend in der Datenbank gespeichert.

Benutzer AktionErgebnis
Klick auf den eigenen Namen in der NavbarProfilseite mit Formular
Daten bearbeiten und „Speichern" klickenProfil wird gespeichert, Erfolgsmeldung erscheint

UC5 – Merkliste erstellen und verwalten

Akteure: Registrierter Benutzer

Beschreibung: Eingeloggte Benutzer können Filme und Serien zu ihrer persönlichen Merkliste hinzufügen oder davon entfernen. Die Merkliste ist benutzerspezifisch und wird über den Auth0-Sub-Identifier in der Datenbank gespeichert. Auf der Merklisten-Seite werden alle gespeicherten Einträge angezeigt.

Benutzer AktionErgebnis

Beschreibung: Benutzer mit Admin-Rolle haben Zugriff auf den Admin-Bereich. Dort können Filme und Genres angelegt, bearbeitet und gelöscht werden (vollständiges CRUD). Zusätzlich können Admins eine Übersicht aller Merklisten-Einträge aller Benutzer einsehen. Die Admin-Rolle wird in Auth0 vergeben.

b) Implementierung

1. Architektur

Pick and Look ist als Single-Page Application (SPA) mit getrenntem Frontend und Backend realisiert:

SchichtTechnologieBeschreibung
Frontend Vue 3, Vite, Pinia, Vue Router SPA mit Composition API; Routing, State Management und HTTP-Calls
Backend Spring Boot 3.2, JPA/Hibernate REST-API mit JSON; Validierung über Bean Validation
Datenbank (Prod) PostgreSQL (render.com) Gehostete PostgreSQL-Instanz auf render.com
Datenbank (Dev) H2 (In-Memory) Automatisch beim Start der lokalen Entwicklungsumgebung
Authentifizierung Auth0 (OAuth 2.0 / OIDC) Login, Registrierung und Rollenverwaltung via Auth0

5. Routing und Navigation

Das Routing wird über Vue Router mit Hash-History realisiert (createWebHashHistory()). Hash-History ist für das Deployment auf GitHub Pages notwendig, da der Server keine serverseitigen Weiterleitungen für SPA-Pfade unterstützt. Lokal wird Web-History verwendet.

Die Navbar zeigt rollenabhängige Links: Merkliste und Profil sind nur für eingeloggte Benutzer sichtbar; Admin und Film hinzufügen nur für Benutzer mit Admin-Rolle.

6. State Management

Der Zustand der Merkliste wird in einem Pinia-Store (stores/watchlist.js) verwaltet. Der Store hält die Liste der gemerkten Filme sowie ein Set mit den IDs für schnelle Existenzprüfung. Er wird beim Login automatisch mit den Daten des Benutzers aus dem Backend befüllt.

7. Authentifizierung

Die Authentifizierung ist vollständig an Auth0 ausgelagert. Der Axios-Interceptor in api.js hängt bei jeder API-Anfrage automatisch den JWT-Bearer-Token aus Auth0 an den Authorization-Header. Die Admin-Rolle wird als Custom Claim (https://pickandlook.com/roles) im JWT-Token übermittelt und im Frontend ausgewertet.

8. Hartcodierte Werte (Erklärung)

Fallback-URL http://localhost:8080 in api.js:
Der Wert 'http://localhost:8080' dient als Fallback für die lokale Entwicklungsumgebung, wenn keine .env-Datei gesetzt ist. Im Produktionsbetrieb (GitHub Pages) wird der Wert der Umgebungsvariable VITE_API_URL aus .env.production verwendet, die auf die render.com-Backend-URL zeigt. Dieser Fallback ist bewusst gesetzt und stellt keinen Fehler dar.

c) Bereitstellung

1. URLs

Frontend (GitHub Pages)

https://htwg-in-schneider.github.io/frontend-pickandlook/

Das Frontend wird automatisch via GitHub Actions auf GitHub Pages deployt, sobald ein Push auf den main-Branch erfolgt.

Backend (render.com)

https://backend-pickandlook.onrender.com

Das Backend läuft als Docker-Container auf render.com (Free Tier). Die PostgreSQL-Datenbank ist ebenfalls auf render.com gehostet.

Hinweis zum Free Tier: Der Backend-Service auf render.com schläft nach 15 Minuten Inaktivität ein. Beim ersten Aufruf kann es daher 30–60 Sekunden dauern, bis die Filme geladen werden, während der Service aufwacht. Dies ist eine bekannte Einschränkung des kostenlosen Plans.
